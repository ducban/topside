Install

macOS 14 or later, Apple silicon. No sudo.

curl -fsSL https://topside.ducban.com/install.sh | sh

The script downloads the latest release from GitHub, checks it against its SHA-256, verifies the signature, and copies the app beside any copy already in /Applications. The swap happens once the new copy is whole, so a run that fails leaves you the app you had. Read it first; it's under 90 lines.

Topside opens when the script finishes. It has no Dock icon and no menu bar item. If you're hunting for it, look up: it's the black pill at the notch, or at the top center of a display that has none.

Update

Run the same command. It quits the running Topside, swaps the app and opens it again. Your settings sit in the data folder, which the installer never touches.

When an update changes the pi or omp extension or the OpenCode plugin, Topside rewrites its own file at launch. Sessions that were open at the time need /reload in pi, or a restart in omp and OpenCode.

Remove

  1. Hover the island, click the gear, open Integrations and switch everything off. That takes Topside's entries out of each agent's config and puts your status line back.
  2. In General, switch off "Open at login".
  3. Click the power button beside the gear to quit.
  4. Delete /Applications/Topside.app.
  5. For a clean slate, delete ~/Library/Application Support/Topside too.

To install somewhere else, name a folder you own: curl -fsSL https://topside.ducban.com/install.sh | TOPSIDE_INSTALL_DIR=~/Applications sh. TOPSIDE_NO_OPEN=1 installs without starting the app.

Claude Code

Every entry Topside adds ends with # topside-managed, which is how switching off finds its own hooks and nobody else's. Yours are kept. Before each write the file is copied to settings.json.topside-backup-<timestamp> beside it.

The file is written back with its keys sorted. If you keep it in git, expect one loud diff and quiet ones after.

If CLAUDE_CONFIG_DIR is set, Topside follows it. With Topside closed, the hook prints nothing and Claude Code asks in the terminal as it always did.

Two kinds of session never show: one-shot runs (claude -p), and a background session until you open it with claude attach.

Codex CLI

Codex runs a hook only after you trust it. Open Codex, run /hooks and approve Topside's. Topside doesn't write that trust for you, and shouldn't be able to. Until you do, Codex rows say "Not tracked: run /hooks in Codex". You'll be asked again if the app moves to another folder, because the hook's command changes with it.

Codex takes allow or deny from a hook and nothing else, so its requests have those two answers. codex exec and codex review don't show. If CODEX_HOME is set, the hooks go there.

pi and omp

These two have no hooks; they load TypeScript extensions. Topside adds one file, marked topside-managed on its first line. Switching off deletes it. A topside.ts without the marker is yours and is left alone.

A session that was open before the switch shows as "Not tracked yet" with what to do: /reload in pi, a restart in omp, which loads extensions only when it starts.

pi and omp run tools without asking. "Ask before risky commands" puts a request on the island in front of a short list: rm -rf, sudo, a forced git push, git reset --hard and curl … | sh, including when they hide inside xargs or sh -c. You have 25 seconds; after that the command is blocked. With Topside closed, the command just runs.

They bill by the token, so the header shows what the session you've picked has cost, as $0.42 · 182K, or 26K TOKENS when it cost nothing.

OpenCode

OpenCode loads plugins, not hooks, so Topside adds one file, marked and removed the same way as pi's. It goes under $XDG_CONFIG_HOME/opencode/plugins when that's set. OpenCode reads plugins when it starts, so a session that was already open says "Not tracked yet" until you restart it.

Unlike pi, OpenCode asks for permission itself, about whatever its permission config sets to ask. Its prompt stays up while the island asks too, and the first answer wins. You get Allow, Deny and Always; Always covers the pattern OpenCode offers, git status * say, in that project until OpenCode restarts. A question with options comes up on the question card. opencode run and opencode serve don't show.

OpenCode has moved its plugin API before. If a version stops taking Topside's answers, its requests don't open on the island at all: the row says it's waiting and you answer in OpenCode. It bills by the token, so the header shows cost and tokens; on OpenCode Free or Zen, which cost nothing, just the tokens.

OpenCode Go turns cost nothing until you hit a limit, so the limits are the number worth watching. On a Go model the header shows Go's five-hour and weekly windows, the same way it shows Claude's. After each turn the plugin asks opencode.ai with the opencode-go key OpenCode saved when you logged in. That key goes to opencode.ai and nowhere else.

Help wanted. Whoever writes Topside doesn't pay for Go. This part was built from OpenCode's own source and tested against a fake server, never a real account. If you're on Go, finish a turn, compare the header with your Console, and open an issue to say whether they match. "It works" is a useful report too.

Plan usage

The header shows the limits of the session you've picked, as 5H 39% 7D 61%, going orange at 50% and red at 80%. Claude Code's come through its status line, which is why that switch exists; switching off puts your original status line back. Codex's are read from its own session file and need no switch. OpenCode Go's are fetched after each turn, as described above under OpenCode.

When the context fills up

Once a session goes past 20% of its context window, the island opens a card when its turn ends. That's any agent: Claude Code, Codex, pi, omp or OpenCode. It has three keys: Later (esc), Jump (^J) and Compact (^Y). Compact jumps to that session's terminal and types /compact for you in tmux, WezTerm, Orca, iTerm2 and Terminal.app. Any other terminal gets it on the clipboard to paste. Each session gets one card, and another only after it compacts. You can move the line or turn the card off in Notifications.

Where the number comes from depends on the agent. Claude Code's comes through the same status line wrapper as plan usage, so that switch has to be on. Codex's is read from its session file. pi, omp and OpenCode send theirs at the end of each turn, and they only start after they load the new extension or plugin, so run /reload in pi and restart omp and OpenCode once after updating. Codex's footer takes a fixed amount off before it says "% left", so the two numbers won't quite match.

The island

The pill

It wears the style you picked. On the board, the left side is the newest session's agent as a flight code (CLD, CDX, PI, OMP or OPC) and the right side is a flap per session, newest first, up to five, with the first letter of its status. In the kitchen, the left side is the printer's light with a red count of waiting tickets, and the right side is a tiny rail with a paper stub per session.

BoardKitchenThe session is
WAn orange stub, hanging lower; the light blinks amberWaiting for you: a permission request or a question.
BA blue stubWorking. B for boarding.
AA green stubDone with its turn. A for arrived.
PA grey stubIdle. P for parked.

A reminder turns the flight code red and blinking and the status word to DELAYED, or the printer's light red. Right after you answer, the board's flaps flip to OK and the kitchen stamps a green OK.

The list

Hover the pill or click it. On the board each session is a departure: its age, its name in Claude Code (or its folder), the agent, a status word and what it's doing now. In the kitchen it's a ticket on the rail. The list opens newest first with nothing picked; click a row or a ticket for its prompt, its last reply and a Jump key.

Under a picked session sit two quiet links. "Hide this folder" leaves out every session in that folder. "Hide prompts like it" leaves out every session whose first prompt contains this one's. Either one asks first: it says how many sessions it would hide ("Hide 2 sessions in webapp, and any new one there?") and marks the others it would take, and nothing goes until you press Hide. Keep or esc leaves them. A hidden folder or prompt comes back from Settings, with ×.

On the board, rows past "Sessions shown" fold into "+ N MORE". The kitchen rail always holds five and puts the rest on a spike. A session waiting for an answer always stays in view.

Requests

WhatOpens whenShows
PermissionAn agent asks to run a command or touch a fileThe request, a diff for edits, Allow and Deny
QuestionAn agent asks you to chooseThe options, numbered
Finished turnA turn endsThe last reply

On the board these come down from the notch with keys to press; in the kitchen they print as order tickets you stamp. Claude Code's permission requests have two more answers. "Always" sends back the rule Claude Code itself suggests: accept edits for the session, or allow that exact command in .claude/settings.local.json. It's missing when Claude Code suggests nothing. "Auto mode" switches the session to auto.

A request stays until it's answered, on the island or in the terminal. If the session's terminal is already in front when a turn ends, nothing opens: you're looking at it.

Styles

Settings → Appearance → Style. There are two, both from the Arch version, and Board is the default. Each one is a card there with its own list drawn small, from sample sessions, so you see it before you pick it; a click picks it. The pill and Settings wear the style too.

StyleA requestThe list
BoardA split-flap board lowers from the notch: the time, the session, a status word (WAITING, QUESTION, SECURITY for pi and omp, DELAYED once reminded) and chunky keysDepartures: a lamp, the age, the name, the agent, a status word and what it does now. Click a row for its prompt, last reply and Jump

Answer with a rubber stamp: it lands, the ticket tears off, then the answer goes outA rail under a chalked menu board with the plan limits: five tickets on magnets, waiting ones first and hanging lower, the rest on a spike you click to page through

The keys are the same in every style; the board's keys and the kitchen's stamps show theirs. In Board and Kitchen a click on the pill pins the list: it stays when the pointer leaves, the screen dims behind it, and esc, a click on the dimmed screen or a jump puts it away. The gear pins settings the same way. The kitchen rail always holds five, whatever "Sessions shown" says.

With "Sounds" on, each style plays its own unless you switch "Style sounds" off: the board chimes, rising for a request and falling when a turn ends, and its flaps clack; the kitchen's printer chatters as a ticket feeds, a bell rings when a turn ends, and stamps, tears and magnets sound like stamps, tears and magnets. The app makes them in code; there are no audio files. The speaker left of the gear, in every style, turns all sound on and off.

Settings

The gear in the open list. The speaker beside it turns sound on and off without opening anything. Five tabs.

TabWhat's in it
General"Open at login". "Sessions shown", 1 to 7, 5 unless you change it.

When it's quiet

Most "it's broken" turns out to be one of these.

No island at all
Topside isn't running. It has no Dock icon to tell you so. Open /Applications/Topside.app, and switch on "Open at login" so this happens once.
A Codex row says "Not tracked: run /hooks in Codex"
Codex hasn't trusted the hooks yet, or the app moved. Run /hooks in Codex and approve them.
A pi, omp or OpenCode row says "Not tracked yet"
The session was open before the extension or plugin was. /reload in pi; restart omp or OpenCode.
A session is missing
It's a one-shot run, a background session nobody has attached to, or it matches a folder or prompt you hid. Notifications in Settings lists what's hidden.
Settings shows "Use this copy"
An agent's hook runs a different copy of Topside than the one you're looking at, usually an older one in another folder. The button points the hooks at this one. About says which copy is running.
A turn ended and nothing opened
The session's terminal was in front. Not a bug, though it can feel like one.
The jump reached the app and not the tab
That terminal has no way to pick a tab from outside. See the table.
A pi or omp command was blocked
The risky-command request went 25 seconds without an answer. Run the command again and answer it, or switch the gate off.

Reporting a bug

Start the agent with TOPSIDE_HOOK_LOG set to a file, for example TOPSIDE_HOOK_LOG=/tmp/topside.log claude. Every hook then appends its payload to that file, one JSON object per line. Reproduce the problem, then open an issue. The log holds your prompts and file paths, so read it before you attach it.

What leaves your Mac

Nothing, with one exception. The app talks to a Unix socket and a SQLite file, and has no account to sign in to. The exception is an OpenCode Go session: after each turn the plugin asks opencode.ai for your plan limits, with the key OpenCode already saved. The log above is off unless you set that variable, and it stays where you put it.
