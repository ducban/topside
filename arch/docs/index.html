Install

Arch Linux with Quickshell, and Node 26 or later. Topside comes from npm, which doesn't install system packages or services, so those are a few lines by hand.

sudo pacman -S nodejs npm quickshell
sudo npm install -g topside-arch

Without sudo works too, if npm's prefix is in your home (nvm's is). Then, as yourself rather than root:

topside login on
topside hooks install
topside setup

The first writes the daemon's systemd --user unit, pointed at the node and the script you just ran, and starts it now and at login. The second adds Claude Code's hooks; Agents covers the others. The third puts Topside in your bar: SekaiPop, DankMaterialShell or both, whichever runs. With neither, run topside pill.

Upgrade

Run the npm line again, then topside setup. It refreshes the bar's files and restarts what still runs the old ones: SekaiPop or DMS, and the daemon. Add --no-restart to do that later; it prints the commands instead.

203/EXEC

If systemctl --user status topside says 203/EXEC, the unit points at a /usr/bin/topside that isn't there. Before 0.1.2 the install copied a fixed unit, which fails after an install without sudo. topside setup rewrites a unit Topside wrote and restarts the daemon, so the upgrade lines above fix it.

Remove

Take out what Topside put into your agents first, while the topside command still exists.

  1. topside usage uninstall gives Claude Code its own status line back, byte for byte.
  2. topside hooks uninstall takes out Claude Code's hooks. Add codex, pi, omp or opencode for the ones you installed.
  3. systemctl --user disable --now topside, then rm ~/.config/systemd/user/topside.service.
  4. sudo npm uninstall -g topside-arch.
  5. For a clean slate, delete ~/.local/state/topside and ~/.config/topside too, and the plugin folders in the table below.

AUR

yay -S topside-arch once the AUR takes new accounts again. The package is ready; it installs the user unit in /usr/lib/systemd/user, so topside login on only enables it.

Agents

Claude Code gets hooks from topside hooks install. Requests come with Deny, Always, Allow and Auto mode, and questions with their options. For plan usage in the header, run topside usage install; it wraps your status line and passes its output through.

Codex CLI: topside hooks install codex, then run /hooks in Codex once and trust Topside's entries. Codex skips a hook nobody trusted, so until then its sessions read "Not tracked: run /hooks in Codex". Requests get Allow and Deny only. Plan usage comes from Codex's own session file.

pi and omp have no hooks, so topside hooks install pi or omp writes a small extension. An open pi session picks it up with /reload; omp needs a restart. They run tools without asking. topside gate on asks you first before rm -rf, sudo, git push --force, git reset --hard and curl … | sh; no answer in 25 seconds is a deny.

OpenCode has no hooks either: topside hooks install opencode writes a plugin, and OpenCode loads plugins only when it starts, so restart it. Requests get Deny, Always and Allow, where Always holds for the project until OpenCode restarts, and a question with one part gets its options, with a Deny that tells OpenCode to go on without an answer. Its header shows what the session has cost, or the plan's limits on an OpenCode Go model.

Context. When a turn ends with a session's context past the line you set (20% by default, in the bar's settings), a card says so with Later, Jump and Compact. Compact types /compact into the session in WezTerm, Orca or tmux, and puts it on your clipboard anywhere else. Claude Code's reading needs topside usage install.

Bars and styles

SekaiPoptopside setupBoard or KitchenSettings > Desktop > Plugins > Topside
DankMaterialShelltopside setup, then add Topside in Bar > WidgetsBoard or Kitchenthe ⚙ in its list
Anything elsetopside pillBoard or Kitchentopside pill position|style|text-size

Board, the default, is a split-flap departures board. A request lowers it with the session, its agent and a status word, and a click on the bar entry dims the screen and lowers the full departures. The entry shows the newest session's agent as a flight code, CLD, CDX, PI, OMP or OPC, and a small flap per session: W waiting, B boarding, A arrived, P parked.

Kitchen prints each request as an order ticket you stamp, and the list is a rail of tickets under a chalkboard of your plan usage. Its entry is a printer light, amber and blinking while something waits, and a paper stub per session.

Both always draw in Topside Black, so there's no theme to pick. With sounds on they sound like what they are: chimes and clattering flaps, or a printer, a bell and stamps.

Keys

A card that opens by itself never takes the keyboard, so you keep typing. The keys work once you've clicked the bar entry to open the list, on any bar.

KeyDoes
^YAllow the first request
^NDeny it
^AAlways, when Claude Code offers it
^1…^9Pick an option of the first question
^JJump to the session's terminal
escClose, never answering anything

In Kitchen, ^Y and ^N press the stamp printed on the ticket, so it slams and tears off as a click would. The pill has no keys yet.

Jump

A click on a session, or ^J, walks up its process tree to the terminal window, focuses it with hyprctl, then picks the tab.

Jump needs Hyprland. Other Wayland compositors still get the list and the answers. topside jump <id> does the same from a shell, with an id or a unique prefix from topside status.

When it's quiet

The bar shows OFF, or red dots
The daemon isn't running. systemctl --user status topside says why; topside login on starts it.
A Claude Code session has no row
Check topside integrations: hooks should be this. If it's other, Claude Code still runs an older copy; topside integrations adopt points it here. claude -p runs and background sessions nobody attached to never get a row.
Codex says "Not tracked"
Run /hooks in Codex and trust Topside's entries. A reinstall from another path needs trusting again.
pi or omp says "Not tracked yet"
/reload in pi, or restart omp.
The bar still shows the old version
Run topside setup again. SekaiPop and DMS keep the files they loaded until a restart, and setup does that unless you passed --no-restart or ran it over SSH.
A session is missing on purpose
You may have hidden its folder or prompt. The bar's settings list every hidden entry with a way back.
No sound
Sounds are off by default; the speaker beside ⚙ turns them on. They play with canberra-gtk-play, from libcanberra. A session whose terminal has the focus stays quiet.
